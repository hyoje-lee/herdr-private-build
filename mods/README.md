# Herdr 모드 관리

외부 원본은 `sources/`의 Git submodule로 관리하고, 직접 관리하는 설정과 수정본은 `local/`에 둡니다. 이 문서는 모든 모드에 적용되는 관리 규칙을 다룹니다. 각 모드의 동작, 단축키, 적용 방법은 해당 `local/<이름>/README.md`에 기록합니다.

```text
mods/
├── README.md
├── sources/
│   └── <원본 저장소>/          # Git submodule
└── local/
    └── <모드 이름>/
        ├── README.md          # 해당 모드의 설명과 적용 방법
        └── ...                # 설정 파일 또는 수정한 모드
```

## 관리 규칙

- `sources/` 내부 파일을 직접 수정하지 않습니다. 원본을 수정해야 하면 필요한 모드만 `local/<이름>/`에 복사한 뒤 관리합니다.
- `local/`에는 직접 관리할 파일만 둡니다. 수정하지 않는 원본 파일은 해당 submodule에서 가져옵니다.
- 원본 버전은 부모 저장소에 기록된 submodule 커밋으로 고정합니다. 원본을 갱신할 때에는 관련 로컬 설정과 함께 변경 내용을 검토하고 검증합니다.
- 앱이 생성하는 상태 파일, 개인 설정 백업, 실행 로그는 이 저장소에 넣지 않습니다.
- 새 모드를 추가할 때에는 개별 README를 작성하고 아래 목록에 링크를 추가합니다.

## 원본 준비와 갱신

저장소 루트에서 원본을 준비합니다.

```sh
git submodule update --init --recursive
```

원본을 갱신할 때에는 해당 submodule에서 fetch한 뒤 변경 내용을 확인하고 사용할 커밋을 선택합니다. 관련 로컬 설정까지 검증한 후 부모 저장소에 새 submodule 커밋을 기록합니다.

## 앱에 적용

실제 앱 설정 위치는 `~/.config/herdr-app/`입니다. 모드별 README에 적힌 파일과 절차에 따라 적용합니다.

- 기존 파일을 확인하고 변경 전에 백업합니다. 이름이 같은 모드가 이미 있으면 내용을 비교합니다.
- `keys.json` 같은 설정 조각은 기존 파일에 섹션과 키별로 병합합니다. 파일 전체를 덮어쓰지 않습니다.
- 원본과 로컬 설정 중 어떤 파일을 적용할지는 모드별 README를 따릅니다.
- 적용 후 설정 오류와 실제 동작을 확인합니다. `herdr-app check`는 모드의 초기 로드를 검사하며, 실제 키 입력 검증을 대신하지 않습니다.
